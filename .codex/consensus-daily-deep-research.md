## 2. 매일 처리할 20개 선택

1. `stocks/*.html` 중 파일명이 `NNN_CODE.html` 형식이고 순위 접두사가 `001`부터 `100`까지인 파일을 이름순으로 정렬한다. 공동순위를 포함하므로 현재 정상 대상 수는 105개다.
2. `consensus_rotation_state.json`의 `lastIndex`를 다음 처리 위치로 사용한다. 값이 없거나 범위를 벗어나면 0으로 보정한다.
3. 커서부터 원형 순환 방식으로 최대 20개를 선택한다. 실행 중단 시 이미 판단을 마친 파일 다음부터 정확히 이어져야 한다.
4. 순위 100을 초과한 파일은 이 작업에서 처리하지 않는다.

## 3. 파일별 조사 규칙

파일 하나를 조사·검증·커서 저장까지 완전히 끝낸 다음 파일로 넘어간다.

1. 한경컨센서스를 먼저 확인하고, 다음으로 네이버 증권 기업분석 원문을 확인한다. 두 출처에서 서로 다른 증권사의 개별 리포트를 3개 미만 확인했을 때만 Investing.com·FnGuide 같은 집계 서비스를 보조로 사용한다.
2. 실행일 기준 최근 6개월 이내의 실제 리포트만 사용한다. 최신순으로 최대 5개, 증권사별 최신 리포트 1개만 포함한다.
3. 증권사명, 목표주가, 투자의견, 발행일, 실제 원문 URL을 모두 확인한 행만 작성한다. 하나라도 확인되지 않으면 추측하지 말고 그 행을 제외한다.
4. 모든 행의 이름은 `<a href="실제 URL" target="_blank" rel="noopener">`로 감싼다. 링크 없는 행은 만들거나 유지하지 않는다.
5. `Buy`와 `매수`는 `매수`, `Hold`·`Neutral`·`MarketPerform`은 `중립`으로 표시한다. 그 밖의 의견은 의미를 추측해 바꾸지 말고 원문 표기를 유지한다.
6. 평균 목표주가는 포함된 개별 리포트 목표가의 산술평균으로 계산한다. `현재가 대비`는 파일의 `dp-price`를 기준으로 소수점 한 자리까지 계산하고 부호와 `dp-up`/`dp-down` 색상을 일치시킨다. 집계 서비스의 평균·최고·최저 행을 사용한 경우 집계 평균을 요약값으로 사용한다.
7. 검증 가능한 최신 정보가 부족하면 파일을 수정하지 않고 스킵한다. 컨센서스 블록이 없는 파일은 신뢰할 수 있는 리포트가 충분할 때만 블록과 `SECTION_IDS`의 `consensus` 항목을 함께 추가한다.
8. 수정 범위는 `dpAcc-consensus` 블록과 필요한 경우 `SECTION_IDS` 안의 `consensus` 항목으로 제한한다. 다른 섹션, 차트 데이터, CSS와 JavaScript는 수정하지 않는다.

## 4. 파일별 검증과 저장

1. 표의 모든 행 수와 실제 링크 수가 같은지 확인한다.
2. 표시한 증권사·목표주가·의견·날짜가 연결된 원문과 일치하는지 확인한다.
3. 최신순 정렬, 증권사 중복, 6개월 초과 자료, 평균 목표가와 상승여력 산식을 검사한다.
4. 전체 HTML의 `div` 태그 균형, `<script>`/`</script>` 2개씩, 컨센서스 블록과 `SECTION_IDS` 일치를 검사한다.
5. 수정 전후에서 허용 범위 밖 내용이 바뀌지 않았는지 확인한다.
6. 파일이 변경됐다면 해당 종목 파일만 별도 커밋한다. push 직전에 `origin/main`을 fetch하고 rebase하며, 충돌 시 덮어쓰지 말고 중단한다. 정상일 때 `origin/main`에 push한다.
7. 변경 또는 스킵 판단이 끝나면 `consensus_rotation_state.json`의 `lastIndex`를 다음 파일 위치로 옮기고 `lastRunUtc`를 UTC ISO 8601 시각으로 갱신한다. 상태 파일은 별도 커밋하고 같은 안전 절차로 push한다.
