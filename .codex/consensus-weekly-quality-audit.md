# Weekly analyst consensus quality audit

이 문서는 Codex 구독 세션이 주 1회 수행하는 읽기 전용 품질검사 절차다. 최신 리포트를 다시 심층 조사하거나 파일을 수정·커밋·push하지 않는다.

## 1. 안전한 시작과 범위

1. 저장소 `C:\Users\h24795\Documents\Codex\2026-08-25\aslkdjf\work\kospi10000`에서 `gh auth setup-git`을 실행한다.
2. 사용자 변경이나 미커밋 변경이 있으면 파일을 건드리지 말고 현재 체크아웃을 읽기 전용으로 검사한다. 그 상태를 결과에 명시한다.
3. 작업 트리가 깨끗할 때만 `origin/main`을 fetch하고 `pull --rebase`한다. 충돌이 발생하면 중단하고 덮어쓰지 않는다.
4. `stocks/*.html` 중 순위 접두사가 `001`부터 `100`까지인 모든 파일을 검사한다. 공동순위를 포함한 현재 기대 파일 수는 105개이며, 실제 개수가 다르면 오류로 보고한다.

## 2. 전체 105개 품질검사

각 파일에서 다음 항목을 검사하되 어떤 파일도 수정하지 않는다.

1. `dpAcc-consensus` 블록 수가 0개 또는 1개인지 확인한다. 블록이 없는 파일은 `SECTION_IDS`에도 `consensus`가 없어야 하며, 이를 오류가 아닌 커버리지 공백으로 별도 집계한다.
2. 블록이 있는 파일은 `SECTION_IDS`에 `consensus`가 정확히 포함돼야 한다.
3. 표의 모든 행이 4개 셀을 가지며, 이름에 실제 `https://` 원문 링크와 `target="_blank" rel="noopener"`가 있는지 확인한다. 행 수와 링크 수가 같아야 한다.
4. 증권사명, 목표주가, 의견, 날짜 형식을 검사한다. 최근 6개월을 넘긴 행, 월 단위 날짜, 증권사 중복, 최신순이 아닌 정렬은 각각 구분해 보고한다.
5. 개별 증권사 행에서는 목표주가 산술평균과 표시된 평균 목표주가가 일치하는지 확인한다. 집계 평균·최고·최저 형식은 집계 평균을 기준으로 한다.
6. 파일의 `dp-price`와 평균 목표주가로 `현재가 대비`를 다시 계산해 소수점 한 자리 값, 부호, `dp-up`/`dp-down` 색상이 맞는지 확인한다.
7. 전체 문서의 `<div>`/`</div>` 균형, `<script>`/`</script>` 개수 2/2, 컨센서스 블록 내부 표와 요약 구조를 확인한다.
8. 중복 URL을 합친 뒤 모든 출처 링크에 실제 GET 요청을 보내 상태를 확인한다. HTTP 403처럼 봇 차단 가능성이 있는 응답은 깨진 링크와 분리해 경고로 보고하고, 404·410·DNS 실패·잘못된 URL은 오류로 보고한다.
9. 네이버 증권 기업분석 원문 링크는 증권사·목표주가·의견·작성일을 원문과 자동 대조한다. 그 밖의 출처는 접근 가능 여부와 페이지에서 확인 가능한 필드를 대조하고, 자동 확인이 불가능하면 `수동 확인 필요`로 분류한다.

## 3. 결과 보고

다음 순서로 간결하게 보고한다.

1. 검사 파일 수, 컨센서스 블록 수, 커버리지 공백 수
2. 표 행 수와 링크 수, 정상 접근·봇 차단·깨진 링크 수
3. 수치·날짜·정렬·중복·HTML·원문 불일치 오류 수
4. 오류 파일과 구체적인 사유
5. 수동 확인이 필요한 출처

오류가 없어도 검사 범위와 0건 결과를 명시한다. 이 작업에서는 자동 수정, 커서 변경, commit, push를 하지 않는다.
