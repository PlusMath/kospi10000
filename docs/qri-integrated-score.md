# QRI 통합 매력도 (model qri-1.0)

기업체력 Q · 상대가치 R · 내재가치 I를 하나의 100점 만점 상대 비교 점수로 합친다. 기술적 분석은 포함하지 않는다.

> 통합 매력도는 기업체력 45%, 상대가치 15%, 내재가치 40%를 반영한 상대 비교 점수입니다. 기술적 분석은 포함하지 않습니다. 점수는 상승 확률이나 절대 저평가를 뜻하지 않습니다.

이 문서의 지표 정의, 백분위 방식, 45/15/40 가중치, 게시 임계값은 이 프로젝트를 위한 설계안이다. 수익률 백테스트로 검증한 최적값이 아니다. 요인을 구분하고 척도를 맞춰 합성하는 방식은 MSCI Core Multiple-Factor Indexes Methodology(2025-04)를 참고했지만, 그 산식을 복제한 것은 아니다.

## 최종 산식

```
통합 = 0.45 × Q + 0.15 × R + 0.40 × I
Q, R, I = 각 원점수를 같은 정규화 모집단 U 안에서 평균 동순위 백분위(0~100)로 바꾼 값
```

- **백분위** = 100 × (less + (equal − 1)/2) / (n − 1)
  - 동점은 같은 값을 받는다. 전원 동점이면 50이다.
  - 동점 판정 허용오차는 1e-9로, 부동소수 잔차만 흡수한다.
- **표시값과 순위**
  - 표시 score는 반올림 전 합계를 소수 첫째 자리에서 반올림한 값이다.
  - 등급도 이 표시 score로 판정한다.
  - 순위는 반올림 전 합계의 내림차순이고, 동점이면 종목코드 오름차순이다.
- **하지 않는 것**: 최종 합계에 다시 백분위를 적용하지 않고, min-max로 늘리지도 않는다.
- **등급**

  | 점수 | 등급 |
  |---|---|
  | 80 이상 | 매우 높음 |
  | 65 이상 | 높음 |
  | 45 이상 | 보통 |
  | 30 이상 | 낮음 |
  | 30 미만 | 매우 낮음 |
  | 값 없음(null) | 평가 보류 |

### 스펙 초안과 달라진 결정 (2026-11-17)

| 항목 | 초안 | 확정 | 근거 |
|---|---|---|---|
| 가중치 | 40/20/40 | **45/15/40** | R과 I의 순위상관이 약 0.65다. 40/20/40이면 최종 순위에 R(상관 0.70)이 Q(0.55)보다 크게 작용한다. 45/15/40에서 세 축 영향이 Q 0.64, R 0.62, I 0.72로 비슷해진다. |
| EPS 성장률 | 선형 −50%=0 ~ +100%=100 | **로그 척도**: 예상/직전 EPS 비율 1/3배=0, 1배=50, 3배=100 | 성장 0%가 33.3점이면 감익이 거의 없는 기업이 흑자전환(50점)보다 낮아진다. 100점에 몰리는 종목이 33개에서 22개로 준다. |
| 우선주 R | 미정 | Forward PER·PBR은 **업종 중앙값 × 그 우선주의 직전 60개월 평균 우선주/보통주 가격 비율**과 비교한다. 배당은 우선주 자체 수익률을 쓴다. | 평소 할인만큼은 상쇄하고, 평소보다 더 싼지만 반영한다. 평균은 내재가치 엔진의 `pref_ratio`와 같다. |
| 업종 비교군 | 금융 1개 그룹, 유틸리티는 건설·전력기기·소재에 섞임 | **은행·카드 / 보험 / 증권 / 유틸리티** 분리 | 한전KPS·SK가스 등이 PER 높은 업종과 비교돼 R이 과대평가됐다. |
| 컨센서스 없는 종목 | — | 스펙대로 **평가 보류**(대체값 없음) | 증권사 추정이 3곳 미만이면 네이버도 N/A다. |

## 축별 정의

### Q 기업체력 (ROE 15 / EPS 성장률 15 / 재무안전성 10)

- **ROE 추정치(EPS/BPS)**
  - 점수 = clamp(50 + 5 × (ROE − 업종 ROE 중앙값)). 단위는 %와 %p다.
  - 업종 비교군이 5개 이상 있어야 한다. BPS가 0 이하면 invalid다.
  - 평균 자기자본을 쓰는 정식 ROE와는 같지 않다.
- **EPS 성장률**
  - 올해 컨센서스 EPS ÷ 직전 결산연도 EPS의 로그 척도다(위 표).
  - 흑자전환이면 50점이다.
  - 컨센서스로 예상 적자가 확인되면 0점 관측이다.
  - 컨센서스가 없으면 missing이다.
- **재무안전성**
  - 같은 업종 안에서 부채비율이 낮을수록 높은 백분위다. 비교군은 3개 이상이어야 한다.
  - 부채비율이 음수면 invalid다.
  - **금융업(types.json '금융')은 설계상 미적용**이다. Q는 ROE와 성장률 15/15로만 계산하고 '금융업 건전성 지표 미반영' 배지를 붙인다.
- **우선주**: 보통주 발행기업의 Q를 그대로 공유한다.
- **게시 조건**
  - ROE 관측이 필수이고, 관측 항목이 2개 이상이며, coverage가 0.75 이상이어야 한다.
  - 금융업은 ROE와 성장률이 모두 있어야 한다.
  - 일반 기업에서 ROE와 재무안전성만 있으면 25/40 = 0.625라 미달한다. 그래서 성장률(컨센서스)이 사실상 필수다.

### R 상대가치 (Forward PER 25 / PBR 20 / 배당 15)

- **Forward PER·PBR**
  - 점수 = clamp(100 × (0.5 − ln(rel)/(2 ln 3))). rel = 종목 배수 ÷ 업종 중앙값이다.
  - 중앙값의 1/3이면 100, 같으면 50, 3배면 0이다.
  - 비교군은 시가총액 4,000억 이상 KOSPI이고(`data/peer_universe.json`, 7일 갱신), 5개 이상이어야 한다.
  - 컨센서스 예상 적자는 Forward PER 0점 관측이다. PBR이 0 이하면 invalid다.
- **배당**
  - 무배당은 0점이다.
  - 배당이 있으면 무배당을 포함한 전 종목(비우선주) 평균 동순위 백분위다.
  - 배당 데이터가 없으면 missing이다. 무배당으로 추정하지 않는다.
- **게시 조건**: Forward PER과 PBR이 모두 관측돼야 하고, coverage가 0.75 이상이어야 한다. 배당만 없으면 45/60 = 0.75로 통과한다.

### I 내재가치

- **원점수**
  - P는 Q·R과 같은 날의 종가다. L·H는 내재가치 하단·상단이다(종목 페이지 박스와 같은 마지막 분기).
  - V = √(L·H), x = ln(V/P)
  - x ≥ 0이면 50 + 50x/ln2, x < 0이면 50 + 50x/ln4, 그다음 clamp
  - 주가/가치 0.5배 = 100, 1배 = 50, 2배 = 25, 4배 = 0이다.
- **함께 저장하는 값**
  - 주가/가치 = P/V
  - 중간값 안전마진 = 1 − P/V, 하단 안전마진 = 1 − P/L (음수도 보존)
  - 중간값까지 상승여력 = V/P − 1
  - 상단/하단 비율 = H/L
- **평가 보류 사유**
  - hold(고성장·적자 참고값)
  - 평가 제외(리츠·인프라펀드)나 엔진 오류
  - 평가방법 정보 없음
  - 상하단이 유효하지 않음(0 이하, 역전, 비유한값)
  - 박스 분기와 엔진 분기 불일치
- **평가방법 커버리지**
  - 커버리지 = 성공한 방법의 **원래** 가중치(`engine.WEIGHTS`) 합 ÷ 설계상 가중치 합이다. 0.70 이상이어야 한다.
  - 복수 방법 모델은 성공한 방법이 2개 이상이어야 한다.
  - 설계부터 단일 방법인 '저수익·회복' 유형은 '단일 평가방법' 표시만 붙이고 허용한다.
- **경고**: 방법 간 spread > 2, 일부 방법 누락, 주가 > V, 하단 안전마진 음수. 경고는 감점하지 않고 표시만 한다.

## 공통 결측 규칙과 게시

- **관측으로 치는 상태**: valid, zero_dividend, loss, turnaround
- **eligible에는 넣고 관측에서는 빼는 상태**: missing, parse_error, insufficient_peers, stale, invalid
- **eligible에서도 빼는 상태**: designed_not_applicable
- **축 원점수** = Σ(가중치 × 점수) / 관측 가중치. 축마다 coverage와 실효 가중치를 기록한다.
- **세 축 중 하나라도 산출 불가면** 통합 score는 null이다. 다른 축으로 가중치를 재분배하지 않는다.
- **정규화 모집단 U**
  - 세 축 원점수가 모두 있고, 가격 기준일이 전체 기준일과 같은 종목 전체다.
  - 기술점수, 검색, 즐겨찾기, 업종 필터, 페이지와 무관하다.
  - **U가 30개 미만이면** 통합점수 전체를 '비교 표본 부족'으로 보류한다. 30은 검증된 안전선이 아니라 설정값이다.
- **기준일**
  - 사이트 밖 비교군 캐시가 7일 이상 지났으면 PER·PBR·ROE 항목이 stale이 된다.
  - 서로 다른 가격 기준일을 섞은 통합점수는 게시하지 않는다.

## 해석상 주의

- 80점은 상위 20%라는 뜻도, 상승확률 80%라는 뜻도 아니다.
- 50점은 '주가 = 가치'가 아니다. 그 해석은 I 원점수에만 해당한다.
- 시장 전체가 비싸도 상대적으로 높은 점수가 나온다. 비교 모집단이 바뀌면 원점수가 그대로여도 점수가 달라진다.
- Q·R·I는 독립 요인이 아니다.
  - 컨센서스 EPS는 Q 성장률과 R Forward PER에 함께 들어간다.
  - R과 I는 둘 다 주가를 이익·자본과 비교한다(순위상관 약 0.65).
- **금융업**
  - 금융업 건전성 지표는 반영하지 않는다.
  - 2026-11-17 데이터에서 금융업의 Q 백분위 중앙값은 41(비금융 52)인데, I는 78(비금융 44)로 높다.
  - 내재가치 엔진이 한국 금융주를 체계적으로 싸게 본다. 엔진 개선은 별도 과제다.
- **컨센서스·모델 의존**
  - 컨센서스가 없는 종목은 Q·R이 함께 보류된다.
  - I는 평가 엔진의 유형 분류와 요구수익률 12%에 의존한다.

## 데이터 흐름과 파일

```
update_daily_charts.ps1  ── data/fundamental_score.json
  │   지표별 qri_status, 업종 median·peer_n, 컨센서스·직전 EPS, 종가(price)
  ├─ valuation/run_daily.py ── data/intrinsic_value.json
  │   종목별 detail: 평가 유형, 원래 가중치, 성공·누락 방법, 커버리지, spread, 분기
  │   + errors(평가 불가 사유)
  └─ python -m integrated_score.run_daily ── data/integrated_score.json
      ├─ index.html '매력도별 보기'
      │   통합·기업체력·상대가치·내재가치순 + 별도 기술적 매력순
      │   표 옆 '통합 매력도 상위' 카드
      └─ js/chart-common.js
          종목 상세 상단 통합 매력도 카드(예전 기본점수 카드는 숨김)
```

| 파일 | 역할 |
|---|---|
| `integrated_score/config.py` | 가중치·임계값·등급·도움말 |
| `integrated_score/scoring.py` | 순수 계산(입출력 없음) |
| `integrated_score/run_daily.py` | 입력 스냅샷 읽기, 구 형식 호환, 출력(원자적 교체) |
| `tests/integrated_score/` | 계산·배치 테스트 |

- **입력 고정**: 입력 파일은 한 번만 읽는다. 저장 직전에 해시를 다시 확인해서, 실행 중 파일이 바뀌었으면 게시하지 않는다(exit 2).
- **실패 시 동작**: 배치가 실패하면 기존 파일과 이전 as_of_date가 그대로 남는다. 화면은 '이전 기준일 자료'로 표시한다.
- **구 형식 입력**
  - 2026-11-17 이전 형식(`qri_status`가 없음)이면, 업종 중앙값을 같은 그룹에서 상·하한에 걸리지 않은 종목의 백분위로 역산한다.
  - 적자 여부는 사유 문장을 파싱하지 않는 한 알 수 없으므로 missing으로 둔다.
  - 가격은 index.html 시세를 쓰되, 기준일을 대조한 경우에만 쓴다.

## 실행·검증

```
python -m integrated_score.run_daily --dry-run          # 계산·요약만 출력, 저장 안 함
python -m integrated_score.run_daily                    # data/integrated_score.json 저장
python -m integrated_score.run_daily --snapshot-dir DIR # 날짜별 스냅샷도 저장(일일 배치는 integrated_score/.snapshots, git 제외)
python -m pytest tests/integrated_score -q
```

`--skip-fetch`는 다른 배치와 옵션을 맞추려고 둔 것이고 아무 동작도 하지 않는다. 이 배치는 원래 수집을 하지 않는다.

## 미래 성과 검증(별도 과제)

- 현재 구현만으로 백테스트 완료나 수익률 개선을 주장하지 않는다.
- 출력에는 model_version, as_of_date, 입력 해시, 날짜별 스냅샷을 남긴다.
- 나중에 당시 공개된 재무·컨센서스, 당시 유니버스, 거래비용으로 동일가중 QRI와 비교할 수 있게 하기 위해서다.
- 현재 엔진이 다시 계산한 과거 밴드를 '당시 알 수 있던 값'으로 간주하지 않는다.
